## Les modes de travail
type: titre

Une fenêtre, plusieurs façons de travailler.
Vous n'en utilisez qu'une, et vous passez à côté du reste.

::: notes
Module court mais rentable : la plupart des gens font tout dans le chat web, y compris ce qui devrait vivre ailleurs.

Question d'ouverture : « quand vous ouvrez l'outil le matin, vous cliquez où ? »
:::

---

## La carte
type: concept

| Surface | Ce que vous faites | Ce qui persiste |
| --- | --- | --- |
| **Chat** | Vous dialoguez : question, brainstorm, relecture | La mémoire — les thèmes retenus au fil des échanges |
| **Cowork** | Vous déléguez : « fais-moi ça », vous revenez quand c'est prêt | Mémoire + dossiers locaux + tâches planifiées |
| **Code** | Vous opérez un dépôt : fichiers, terminal, versionnage | Le dépôt, les fichiers de travail, un fichier d'instructions |
| **Design** | Vous cadrez un visuel : maquette, prototype, présentation | Le document de design, votre charte |

Chat et Cowork partagent la **même fenêtre** : vous choisissez le mode au moment d'écrire, et vous passez de l'un à l'autre, même en cours de tâche.

::: notes
Ne pas s'attarder sur Design : c'est en accès anticipé, et pour un profil commercial c'est marginal. Le nommer, montrer où c'est, passer.

Ce qui compte, c'est la colonne de droite : ce qui persiste détermine ce que vous n'aurez pas à réexpliquer. Et elle a changé — le chat n'est plus une ardoise qu'on efface.
:::

## Chat ou Cowork : dialoguer ou déléguer
type: concept

Même boîte de saisie, deux régimes.

**Chat** — vous restez dans la boucle. Vous demandez, il répond, vous corrigez, il reprend. La sortie est du texte que vous allez lire ou replacer ailleurs.

**Cowork** — vous avez un livrable clair en tête. Plusieurs étapes, plusieurs sources, vos fichiers, vos outils. Vous décrivez une fois, vous revenez quand c'est fini. La sortie est un fichier terminé ou une action faite.

Un échange en Chat qui se transforme en vraie tâche se bascule en Cowork sans repartir de zéro.

::: notes
Test à faire poser au participant sur ses usages : « est-ce que je veux discuter, ou est-ce que je veux qu'on me rende quelque chose ? »

Exemples : « aide-moi à formuler cette relance » → Chat. « Reprends ces trois exports, nettoie-les et rends-moi un fichier propre » → Cowork.

Cowork tourne dans le cloud : la tâche continue même app fermée, et vous la suivez depuis le téléphone.
:::

## Ce que la mémoire change
type: concept

Le chat n'oublie plus tout. La **mémoire** est active par défaut : pendant que vous discutez, Claude retient des thèmes — votre métier, vos priorités du trimestre, comment vous appelez vos interlocuteurs.

- Elle est **partagée** entre Chat et Cowork : ce qu'il apprend d'un côté sert de l'autre.
- Elle est **visible et modifiable** dans Réglages > Mémoire, un fichier par sujet.
- Elle retient des **faits résumés**, pas le fil mot à mot.

Conséquence : ce qui doit être fiable et rejouable s'écrit dans un fichier (module 6). La mémoire est un confort, pas un système de référence.

::: notes
Corrige une idée reçue tenace : « le chat ne garde rien ». C'était vrai il y a deux ans, plus maintenant.

Le point à marteler, c'est la dernière ligne. La mémoire évite de réexpliquer son contexte ; elle ne remplace pas un fichier propre quand la précision compte. Un chiffre, une clause, une procédure : ça va dans un fichier, pas dans la mémoire.

Montrer Réglages > Mémoire en direct : voir la liste des thèmes retenus surprend toujours, et rassure sur le contrôle.
:::

## Les Projects : le travail d'un dossier au même endroit
type: concept

Un **Project** regroupe plusieurs conversations — Chat comme Cowork — autour d'un dossier, d'un client, d'un mandat.

Il porte quatre choses :

- **Des instructions permanentes** — qui vous êtes, ce dossier, comment vous écrivez
- **Une base de connaissance** — fichiers, dossiers locaux, liens de référence
- **Des tâches planifiées** — les routines propres à ce dossier
- **Une mémoire propre au projet** — ce qu'il a appris des tâches passées, cloisonnée de vos autres projets

Vous démarrez une conversation ou une tâche Cowork **depuis** le projet, et Claude repart de son contexte.

::: notes
Insister sur Projects, largement sous-utilisé, et sur le mot « regroupe » : c'est là qu'on met toutes les conversations d'un même dossier, pas une par-ci par-là dans l'historique général.

Pour un usage commercial : un Project par client ou par mandat, jamais un Project fourre-tout. La mémoire cloisonnée est l'argument — ce qu'il apprend sur le client A ne fuite pas vers le client B.
:::

## Ce qui vit dans un Project
type: concept

Trois couches, trois comportements :

- **Les instructions** — rechargées telles quelles à chaque nouvelle conversation du projet.
- **La base de connaissance** — relue à la demande, quand la question l'exige.
- **La mémoire projet** — ce qu'il a retenu des tâches déjà menées ici.

Ce qui ne traverse toujours pas tout seul : le **contenu d'une conversation** vers une autre. Pour qu'une trouvaille survive, déposez-la dans la base de connaissance, ou laissez la mémoire en garder le résumé.

::: notes
Nuance clé et souvent mal comprise : la mémoire projet retient des faits, pas le transcript. Si vous avez passé une heure à mettre au point un argumentaire dans une conversation, la mémoire en gardera l'idée, pas les formulations exactes.

D'où la règle qui prépare le module 6 : ce qui a de la valeur et doit se rejouer à l'identique, on l'écrit dans un fichier de la base de connaissance.
:::

## Le réflexe à prendre
type: concept

Avant d'ouvrir une conversation, une question :

> **Qu'est-ce que je veux qu'il se passe ?**

| Ce que vous voulez | Où aller |
| --- | --- |
| Une réponse, un avis, tout de suite | **Chat** |
| Un livrable, à partir de plusieurs sources | **Cowork** |
| Travailler sur un dossier suivi | Dans un **Project** (Chat ou Cowork) |
| Que ça tourne sans vous | Une **tâche planifiée** dans Cowork (module 9) |
| Traiter du volume de fichiers, versionner | **Code** (module 10) |
| Une maquette, une présentation | **Design** |

::: notes
C'est la règle de tri la plus rentable de la journée. La faire appliquer tout de suite sur trois usages réels du participant.

Si un usage tombe dans deux cases, c'est qu'il empile deux tâches. Le découper — ça prépare le module 4.
:::

## Le coût du mauvais rangement
type: piege

Travailler dans le chat général ce qui relève d'un Project a quatre effets, tous invisibles au début :

- Vous **réexpliquez** le dossier à chaque conversation, quinze à vingt lignes à chaque fois.
- Vos réglages de ton et de format sont **incohérents** d'une fois sur l'autre.
- Aucune **mémoire de dossier** ne se construit : la mémoire générale mélange tous vos clients.
- Le travail n'est **pas transmissible** : personne d'autre ne peut reprendre le dossier.

Le dernier point est celui qui coûte le plus cher en entreprise.

::: notes
Le dernier point est l'argument à sortir devant un dirigeant : un Project bien tenu, c'est du travail qu'un collègue reprend en ouvrant le dossier. Un historique de chat éparpillé, non.

C'est aussi ce qui transforme l'IA d'un gadget individuel en outil d'équipe.
:::

## Desktop, web, mobile
type: concept

Les sessions Cowork tournent dans le cloud et **vous suivent** sur les trois surfaces : vous lancez une tâche sur l'ordinateur, vous vérifiez son avancement depuis le téléphone.

Réservé au **desktop** :

- La saisie rapide en surimpression, par-dessus n'importe quelle application
- Le partage d'écran ou de fenêtre, et la dictée
- L'accès aux **dossiers locaux** et le contrôle de l'ordinateur

Le web mobile sert à suivre une tâche et à la débloquer, pas à faire le travail.

::: notes
Vérifier ici, concrètement : l'app desktop est-elle installée ? Le plan est-il le bon ? Si non, l'installer maintenant, sinon la moitié de la journée tombe à plat.

Ne pas passer à la suite sans que ce soit fait. C'est le prérequis matériel des modules 7 et 9.
:::

## Où ranger quoi
type: atelier
livrable: Vos usages répartis par surface, et un Project créé avec ses instructions rédigées

Sur vos usages réels :

1. Listez cinq choses que vous avez demandées à l'outil cette semaine.
2. Pour chacune : dialogue ou délégation ? Chat ou Cowork ?
3. Lesquelles tournent autour d'un même dossier ? Celles-là vont dans un Project.
4. Créez le Project du dossier qui revient le plus souvent.
5. Rédigez ses instructions permanentes : qui vous êtes, ce dossier, comment vous écrivez.
6. Ouvrez une conversation neuve dedans et vérifiez qu'il n'a plus besoin qu'on lui explique le dossier.

::: notes
Pour {{client.prenom}} : le Project du mandat principal. Y déposer le contexte client et les contraintes connues.

L'étape 6 est la validation : si l'outil repose une question dont la réponse est dans les instructions, c'est que les instructions sont mal écrites. On les corrigera au module 6.

Ne pas chercher l'exhaustivité maintenant, on remplira ce Project plus tard.
:::

## À retenir
type: recap

- Chat et Cowork : même fenêtre, deux régimes. Dialoguer, ou déléguer un livrable.
- Le chat n'oublie plus tout : la mémoire retient des thèmes, mais des faits résumés, pas le fil exact.
- Ce qui doit être fiable et rejouable s'écrit dans un fichier, pas dans la mémoire.
- Un Project regroupe les conversations d'un dossier, avec instructions, base de connaissance, tâches planifiées et mémoire propre.
- Le contenu d'une conversation ne passe pas seul à la suivante : il faut le déposer dans la base de connaissance.
- Code pour le volume et le versionnage, Design pour le visuel, tâche planifiée pour ce qui tourne sans vous.
- Le travail sérieux se fait dans l'app ; le web mobile sert à suivre et débloquer.

::: notes
Enchaîner sur le module 3 : « maintenant que vous savez où travailler, il reste à choisir qui vous avez en face et à quel régime de réflexion. »
:::
