## Les modes de travail
type: titre

Le même modèle, quatre espaces différents.
Choisir le mauvais, c'est se priver de la moitié de l'outil.

::: notes
Module court mais rentable : la plupart des gens font tout dans le chat web, y compris ce qui devrait vivre ailleurs.
:::

---

## Quatre espaces, quatre usages
type: concept

| Espace | Pour quoi | Ce qui persiste |
| --- | --- | --- |
| **Chat** | Question rapide, brainstorm | Rien |
| **Projects** | Un dossier suivi dans la durée | Instructions + fichiers de référence |
| **Cowork** | Produire des livrables, manipuler des fichiers | Fichiers de travail |
| **Code** | Terminal, dépôts, automatisation | Le dépôt lui-même |

La colonne de droite est celle qui compte : **ce qui persiste détermine ce que vous n'aurez pas à réexpliquer.**

::: notes
Insister sur Projects, largement sous-utilisé. Un Project = des instructions permanentes + des fichiers que l'outil relit à chaque conversation.

Pour un usage commercial : un Project par client ou par mandat, pas un Project fourre-tout.
:::

---

## Le réflexe à prendre
type: concept

Avant d'ouvrir une conversation, une seule question :

> **Est-ce que je vais refaire ça ?**

- **Non, une seule fois** → chat, et on n'en parle plus.
- **Oui, régulièrement, sur le même dossier** → un Project.
- **Oui, et ça produit un fichier** → Cowork.
- **Oui, et ça devrait tourner sans moi** → une tâche planifiée (module 8).

::: notes
C'est la règle de tri la plus rentable de la journée. La faire appliquer tout de suite sur trois usages réels du participant.
:::

## Le desktop plutôt que le web
type: concept

L'application de bureau donne accès à ce que le navigateur n'a pas :

- Les **fichiers locaux** et les dossiers de travail
- Les **connecteurs** vers {{client.mail}}, {{client.agenda}}, {{client.crm}}
- Les **tâches planifiées** qui tournent sans vous
- Les **skills** et leur exécution

Le chat web est une vitrine. Le travail se fait dans l'application.

::: notes
Vérifier ici, concrètement : l'app desktop est-elle installée ? Le plan est-il le bon ? Si non, l'installer maintenant, sinon la moitié de la journée tombe à plat.
:::

## Où ranger quoi
type: atelier
livrable: Une carte des espaces de travail, avec un Project créé pour le dossier principal

Sur vos usages réels :

1. Listez cinq choses que vous avez demandées à l'outil cette semaine.
2. Classez-les dans les quatre espaces.
3. Créez le Project du dossier qui revient le plus souvent.
4. Mettez-y les deux ou trois fichiers de référence qui le décrivent.

::: notes
Pour {{client.prenom}} : le Project du mandat principal. Y déposer le contexte client et les contraintes connues.

Ne pas chercher l'exhaustivité, on remplira ce Project au module 5 (mémoire et second cerveau).
:::

## À retenir
type: recap

- Quatre espaces : Chat, Projects, Cowork, Code. Ce qui les distingue, c'est ce qui persiste.
- La question de tri : est-ce que je vais refaire ça ?
- Un Project par dossier suivi, pas un Project fourre-tout.
- L'application de bureau, pas le chat web.
