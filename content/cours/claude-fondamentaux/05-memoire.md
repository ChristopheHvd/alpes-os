## Mémoire et second cerveau
type: titre

Le modèle ne se souvient de rien.
Toute la question est de savoir **où** vit ce dont il doit se souvenir.

::: notes
Rappeler la contrainte du module 1 : pas de mémoire entre les sessions. Ce module ne la contourne pas, il l'organise.
:::

---

## Trois façons de se souvenir
type: concept

| Mécanisme | Ce qu'il retient | Qui le contrôle |
| --- | --- | --- |
| **Mémoire automatique** | Ce que l'outil juge utile | L'outil |
| **Fichiers de contexte** | Ce que vous y écrivez | Vous |
| **Outil externe** | Ce que vous y déposez, cherchable | Vous, hors de l'outil |

Le deuxième est le plus rentable, et de loin. C'est un fichier texte. Rien de plus.

::: notes
Beaucoup arrivent en pensant qu'il faut un outil dédié. Commencer par le fichier : c'est gratuit, versionnable, lisible, et ça couvre 80 % du besoin.

L'outil externe (type Hindsight) ne se justifie que quand le volume dépasse ce qu'un fichier peut porter.
:::

## Les deux fichiers qui changent la vie
type: concept

### `aboutme.md`
Qui vous êtes, votre entreprise, votre offre, vos clients, vos priorités du moment, vos contraintes.

Effet : il arrête de reposer les mêmes questions.

### `style.md`
Les tournures que vous ne voulez jamais lire. « Dans un monde où », « je me permets de revenir vers vous », « n'hésitez pas à ».

Effet : le résultat est publiable sans réécriture.

::: notes
Le second fichier est celui qui impressionne le plus en formation, parce que l'effet est immédiat et visible.

Le construire par soustraction : faire relire un texte généré et faire pointer ce qui « sonne IA ».
:::

## Ce qu'on écrit, ce qu'on n'écrit pas
type: concept

**On écrit** ce qui est stable et coûteux à réexpliquer :
l'offre, les segments clients, les contraintes récurrentes, les décisions prises et leur raison.

**On n'écrit pas** ce qui est daté ou retrouvable ailleurs :
les chiffres du mois, l'état d'une affaire, ce que {{client.crm}} sait déjà mieux que vous.

> Un second cerveau qui contient des données périmées est pire qu'un second cerveau vide : il fait produire des réponses fausses avec assurance.

::: notes
Point de vigilance à marteler. Le réflexe naturel est de tout y mettre, et c'est le meilleur moyen de le rendre toxique en trois mois.

Règle simple : si ça change tous les mois, ça vit dans l'outil source, pas dans le second cerveau.
:::

## La structure minimale
type: concept

Un dossier, un fichier par sujet, des liens entre eux.

- Un fichier par **client** ou par **mandat**
- Un fichier par **projet** en cours
- Un fichier par **décision** structurante
- Un index qui pointe vers le reste

Pas de base de données, pas d'outil à installer. Du texte, dans un dossier, sauvegardé.

::: notes
Montrer un vrai second cerveau à l'écran, pas un schéma. L'effet « c'est juste des fichiers » est ce qui débloque les gens.

Si le participant utilise déjà Notion ou Obsidian, partir de là plutôt que d'imposer un dossier de plus.
:::

## Le second cerveau d'un dossier réel
type: atelier
livrable: Le fichier de contexte du dossier principal, relu et chargé dans le Project

Sur votre dossier principal :

1. Écrivez le contexte : qui est le client, ce qu'on lui vend, l'historique utile.
2. Ajoutez les contraintes connues, y compris celles qui ne s'écrivent jamais.
3. Ajoutez les décisions déjà prises et **pourquoi**.
4. Chargez le fichier dans le Project créé au module 2.
5. Posez une question que vous aviez dû expliquer trois fois. Vérifiez.

::: notes
Pour {{client.prenom}} : le contexte du mandat principal. L'étape 3 est celle qu'on saute et celle qui vaut le plus cher — sans le « pourquoi », l'outil repropose l'option déjà écartée.

Prévoir large sur cet atelier, c'est le cœur du module.
:::

## À retenir
type: recap

- Le modèle n'a pas de mémoire : elle vit dans des fichiers que vous contrôlez.
- `aboutme.md` supprime les questions répétées, `style.md` rend le résultat publiable.
- On y écrit le stable, jamais le daté.
- Un fichier par client, par projet, par décision. Du texte, rien d'autre.
- Écrire les décisions **et leur raison**, sinon l'option écartée revient.
